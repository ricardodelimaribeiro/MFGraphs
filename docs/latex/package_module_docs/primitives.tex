\section{High-level explanation}

\texttt{primitives.wl} is the base layer of the active MFGraphs stack. It defines the symbolic atoms and runtime switch that all higher modules rely on. In architectural terms, this file separates the package's foundational vocabulary from all later scenario, system, solver, and graphics logic.

The file has two kinds of responsibility. First, it establishes the core symbolic heads \texttt{j} and \texttt{u}. These are the building blocks from which unknown bundles, systems, solver results, and plotted labels are assembled. Second, it defines the package-wide verbosity flag and the print helper that honours it.

{\sloppy
Congestion regime is not a primitive. The critical-congestion assumption ($\alpha = 1$) is carried by the scenario's \texttt{"Hamiltonian"} data (\texttt{"Alpha"} and \texttt{"EdgeAlpha"}) and enforced by \texttt{criticalCongestionSystemQ} in \texttt{utilities.wl}.\par}

\section{Low-level explanation of functions and functionality}

\subsection*{\texttt{j}}

\texttt{j} is the package's symbolic flow head. In two-argument form, \texttt{j[a,b]} denotes flow on the directed edge from \texttt{a} to \texttt{b}. In three-argument form, \texttt{j[r,i,w]} is the transition flow at junction \texttt{i} from edge \texttt{(r,i)} onto edge \texttt{(i,w)}. It is an amount of flow, not a fraction: summing \texttt{j[r,i,w]} over \texttt{w} gives \texttt{j[r,i]}, and summing over \texttt{r} gives \texttt{j[i,w]}.

Functionally, \texttt{j} is not evaluated in this file; it is a symbolic container. Its main usage is downstream, where \texttt{unknownsTools.wl} constructs families of \texttt{j} variables and \texttt{systemTools.wl} places them into equations, inequalities, and complementarity alternatives.

\subsection*{\texttt{u}}

\texttt{u[a,b]} represents the value-function variable associated with the endpoint \texttt{b} of the directed edge \texttt{(a,b)}. Like \texttt{j}, it is a symbolic head rather than a numerically evaluated function.

Its usage is primarily in Hamilton--Jacobi and switching optimality expressions. Users normally encounter \texttt{u} through systems, solver results, and plotting functions rather than by constructing it manually.

\subsection*{Protection of \texttt{j} and \texttt{u}}

Both heads are \texttt{Protected}. Because \texttt{primitives`} sits ahead of \texttt{Global`} on \texttt{\$ContextPath}, an unprotected head would let a notebook assignment such as \texttt{u = 5} rewrite the package's own symbol, so that every unknown and every solution rule would silently become \texttt{5[a,b]}. With protection, such an assignment fails with a \texttt{Set::wrsym} message. Scoping constructs are unaffected: \texttt{Table[\ldots, \{u, 3\}]}, \texttt{Module[\{u\}, \ldots]}, and \texttt{Function[u, \ldots]} still work. The file calls \texttt{Unprotect[j, u]} before setting the usage messages so that re-evaluating it does not fail.

\subsection*{\texttt{\$MFGraphsVerbose}}

\texttt{\$MFGraphsVerbose} is the global verbosity flag. Its default value is \texttt{False}. When it is set to \texttt{True}, progress and timing messages become visible through \texttt{mfgPrint}.

The intended usage pattern is operational rather than mathematical:

\begin{verbatim}
$MFGraphsVerbose = True;
\end{verbatim}

This is useful when profiling, debugging, or running scripts that benefit from progress visibility.

\subsection*{\texttt{mfgPrint}}

\texttt{mfgPrint[args\_\_\_]} calls \texttt{Print} only when \texttt{TrueQ[\$MFGraphsVerbose]}, and otherwise returns \texttt{Null}. Testing with \texttt{TrueQ} means a non-Boolean flag value is treated as \texttt{False} rather than leaving an unevaluated \texttt{If} as the return value. Its purpose is to centralize debugging and progress output without scattering conditionals across the codebase.

Usage is straightforward: internal code can emit a message through \texttt{mfgPrint} and know that the runtime flag controls visibility.

\section{Usage guidance}

This module is rarely the place where an end user starts working. Instead, it provides the symbolic and runtime substrate that higher-level workflows assume is present. Advanced users extending MFGraphs should understand it well because it defines the vocabulary that recurs everywhere else in the system.
